## 1. 목표

과제 로드맵(`xiaoesp.pdf`)의 목표는 "엣지 머신러닝 시스템에 ROS 2와 AI 기능 추가"다.
우리 팀은 아래 흐름을 실제로 시연하는 것을 성공으로 본다.

> **XIAO 카메라에 사람이 보이면, PC가 사람과 그 방향(왼쪽/가운데/오른쪽)을 판단해 ROS 2 토픽으로 발행한다.**

- **핵심 마감:** 12/2. 종강이 12/9일 수 있으므로 이 날짜까지 전체 흐름을 완성한다.
- **최종 시연:** 12/16. 카메라부터 ROS 2 토픽까지 한 번에 보여준다.

## 2. 범위

| 포함 | 제외 |
|---|---|
| 보드 설정, Blink, Wi-Fi softAP LED 제어 | micro-ROS (XIAO에서 ROS 2 직접 실행) |
| 카메라 사진 SD 저장, CameraWebServer 스트리밍 | 로봇 하드웨어 제어 |
| PC에서 영상 수신 + 사람 탐지 + 방향 판단 | MQTT, Mesh, Round Display, 배터리 |
| ROS 2 토픽 발행 (`/vision/detection` 등) | 3.1 강의자료 내용 |
| (여유 있으면) 보드 위 TFLite Micro 추론 | |

**설계 원칙** (`xiaoesp.pdf` 2~7쪽)
- XIAO는 영상만 보낸다. ROS 2는 PC가 담당한다.
- 영상 경로(HTTP 스트림)와 제어 · 상태 경로(ROS 2 토픽)를 분리한다.

## 3. 시스템 구조

```
┌──────────────┐  Wi-Fi (HTTP MJPEG)   ┌──────────────────────────┐   ROS 2 토픽    ┌────────────┐
│ XIAO ESP32S3 │ ───────────────────▶ │ PC: Python + OpenCV + AI │ ─────────────▶ │ ROS 2 노드 │
│ 카메라 (동혁) │  :81/stream          │ 영상 수신 · 탐지 (동민)  │ /vision/...    │ 통합 (민혁)│
└──────────────┘                       └──────────────────────────┘                └────────────┘
```

- 네트워크: 휴대폰 2.4GHz 핫스팟에 보드와 PC를 같이 연결 (학교 Wi-Fi 미사용)
- ROS 2: Jazzy (Windows는 WSL2 Ubuntu 24.04 + mirrored, Mac은 RoboStack)

## 5. 인터페이스 약속

팀원 사이에 맞물리는 부분이다. **바꾸려면 단톡방에 먼저 공유한다.**

### 5.1 영상 스트림 (동혁 → 동민)
- 주소: `http://<보드IP>:81/stream` (CameraWebServer 기본값)
- 형식: MJPEG. 해상도 ⚠️ 미정 (QVGA 320×240부터 시작해서 FPS를 보고 조정)
- PC에서는 `cv2.VideoCapture(주소)`로 연다. 개발 중에는 웹캠(`0`)을 쓴다.

### 5.2 `/vision/detection` (동민 → 민혁)
⚠️ 메시지 타입 미정. 아래는 제안이다.

- **제안:** 처음에는 `std_msgs/String`에 JSON을 담는다. 커스텀 메시지를 만들지 않아도 돼서 빠르다. 시간이 남으면 `vision_msgs/Detection2D`로 바꾼다.

```json
{
  "object": "person",
  "confidence": 0.87,
  "x": 0.42,
  "y": 0.55,
  "direction": "center",
  "stamp": 1762650000.123
}
```

| 필드 | 뜻 |
|---|---|
| `x`, `y` | 박스 중심 좌표. 화면 크기로 나눈 0~1 값 (해상도가 바뀌어도 그대로 쓰도록) |
| `direction` | `x < 0.33` → `left`, `x > 0.67` → `right`, 나머지 → `center` |
| 발행 조건 | 사람이 탐지된 프레임만. 여러 명이면 신뢰도가 가장 높은 1명 ⚠️ |

### 5.3 `/camera/status`, `/camera/command` (선택)
- `/camera/status`: `std_msgs/String` — `"streaming"`, `"disconnected"` 등 ⚠️
- `/camera/command`: `std_msgs/String` — `"START"`, `"STOP"`

## 6. 비기능 요구사항

측정 후 조정한다. 발표에서 성능 근거로 쓴다(병렬컴퓨팅 관점).

| 항목 | 목표 | 측정 방법 |
|---|---|---|
| 처리 속도 | PC 탐지 포함 10 FPS 이상 | 루프 시간 측정 후 화면에 FPS 표시 |
| 지연 시간 | 카메라 → 토픽 1초 이내 | 화면 타임스탬프와 토픽 `stamp` 비교 |
| 안정성 | 5분 연속 시연 중 끊김 없음 | 스트림 끊기면 자동 재연결 |
| 보안 | Wi-Fi 비밀번호를 git에 올리지 않음 | `secrets.h` / `.env` 사용 |

| 위험 | 영향 | 대응 |
|---|---|---|
| 보드가 1대뿐 (동혁 보유) | 다른 팀원이 실물 테스트를 못 함 | 동민은 웹캠, 민혁은 녹화 영상이나 가짜 메시지로 개발 |

| 펌웨어 도구 미확정 (Arduino IDE / PlatformIO) | 코드 구조와 빌드 방법이 달라짐 | 동혁이 결정 ⚠️ |
| 스트림 FPS 낮음 · 끊김 | 탐지 품질 저하 | 해상도 낮추기, 재연결 코드 |
| Mac ROS 2(RoboStack) 설치 문제 | 동민 PC에서 통합 테스트 불가 | ROS 2는 민혁 PC에서 실행하고, 동민은 Python만 담당 |
| 종강이 12/9일 가능성 | 최종 시연이 당겨짐 | 12/2까지 전체 흐름 완성 |
